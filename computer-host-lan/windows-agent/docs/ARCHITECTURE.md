# Computer Host LAN — Windows architecture 0.2.0-alpha.1

- Integration version 0.5.1-dev.1, Windows agent 0.2.0-alpha.1.
- Native C#/.NET 10 Windows Service under LocalService; Kestrel HTTP on TCP/8765.
- Windows and Linux share the same v2 protocol and generic SmartThings Lua driver.
- Native `DnsServiceRegister` advertises `_computerhost._tcp.local`.
- Persistent installation UUID and heuristic boot ID in protected ProgramData.
- CPU (`GetSystemTimes`), memory (`GlobalMemoryStatusEx`), Windows drive usage,
  uptime (`GetTickCount64`), candidate wired WOL MAC and IPv4 broadcast.
- Opt-in HMAC power command endpoints exactly match Linux protocol v2.
- 32-byte key stored on disk with restricted ACL; no key generated by API.
- Bounded 30-second single-use challenges, constant-time signature comparison,
  per-address rate limiting, and single power operation in flight.
- `LocalService` is granted the shutdown privilege by Windows but it is disabled
  in its token by default. Commands enable that privilege at call time;
  native calls are best-effort. Suspend keeps wake events enabled.
- No forced application closures. HTTP 202 means accepted/scheduled only.
- Main switch OFF requests graceful shutdown; ON sends WOL from the hub.
- Windows device profile exposes Wake/Reboot/Suspend; temperature/load excluded.
- Power disabled unless both agent `-EnablePower` and SmartThings preferences
  opt in. Never expose control token in logs.
- GitHub workflow is installed at repository root under `.github/workflows/`.

### Power limitations

Microsoft does not officially support WOL from Windows Fast Startup or S5;
firmware may still make S5 wake possible. Sleep/Modern Standby capabilities
are hardware-specific. The Wake button sends a magic packet but cannot prove
power state. Test manually per hardware and keep a physical recovery path.
